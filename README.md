# ISP Manager

لوحة تحكم عربية RTL لإدارة مشتركي الإنترنت. نسخة **Demo / Prototype** فعلية، مبنية بـ React + Vite، بتخزين محلي للتطوير، وتخزين مشترك في Cloudflare D1 عند نشر Pages Functions. لا يوجد اتصال حقيقي بـ MikroTik أو Starlink.

## المتطلبات والتشغيل

Node.js 22.13 أو أحدث، وnpm.

```bash
npm install
npm run dev
```

يفتح خادم التطوير على `http://127.0.0.1:5173`. للوصول إليه من جهاز آخر في شبكة محلية، استخدم `npm run dev -- --host 0.0.0.0`.

```bash
npm run build
npm run preview
```

مخرجات البناء داخل `dist/`. التطوير عبر Vite يعمل محلياً دون قاعدة بيانات. النشر على Cloudflare Pages مع المجلد `functions/` يفعّل وضع الخادم ويتطلب الإعداد أدناه.

## الوظائف

- لوحة مؤشرات وحركة إنترنت محاكية للفترات 24 ساعة / 7 أيام / 30 يوم.
- إدارة المشتركين: إضافة وتعديل وحذف بتأكيد، وتجديد 30 يوماً أو مدة مخصصة، وإيقاف وإعادة تفعيل، وتغيير الباقة أو السرعة.
- بحث فوري بالاسم والهاتف وUsername وIP، وفلاتر الحالات والاتصال وترتيب النتائج وعرض دفعات.
- تفاصيل المشترك وكلمة مرور تجريبية مخفية افتراضياً وسجل العمليات والاستهلاك المحاكى.
- إدارة الباقات وأسعارها الاختيارية ومددها. لا يسمح بحذف باقة مرتبطة بمشتركين.
- تنبيهات قابلة للقراءة والمسح، وسجل عمليات، وتقارير مشتقة من البيانات الحالية وسجل التجديدات.
- إعدادات الشبكة والعملة والمدد والحد الأدنى للتنبيه وإظهار الأسعار.
- تصدير JSON واستعادته بعد التحقق العميق من بنيته وتأكيد الاستبدال.
- تهيئة PWA وأيقونات وتخزين مؤقت للإتاحة دون إنترنت للموارد التي فُتحت سابقاً.

## البيانات والتواريخ

تضاف 14 عينة عند **أول تشغيل فقط**، بتواريخ نسبية لليوم الحالي. حذف جميع المشتركين لا يعيد العينات. في الوضع المحلي، البيانات خاصة بالمتصفح والجهاز والأصل المستخدم. في الوضع المشترك، البيانات في D1 وتتاح بعد تسجيل الدخول من أي جهاز. لا يتم نقل البيانات المحلية تلقائياً: اختر الجهاز الصحيح أو ارفع نسخته الاحتياطية عند تهيئة القاعدة. تحفظ البيانات المحلية القديمة دون استبدال، وصدّر نسخة احتياطية دورياً.

التواريخ الداخلية `YYYY-MM-DD`، والعرض `DD/MM/YYYY`. تُحسب الأيام كتواريخ تقويمية، والوقت الحالي وفق `Asia/Baghdad`؛ لا يُستخدم تحويل التاريخ المحلي إلى UTC عند قراءة حقل التاريخ. التفعيل + 30 يوماً = الانتهاء، مثلاً 02/10/2026 → 01/11/2026. الاشتراك ينتهي عند بداية يوم الانتهاء بتوقيت بغداد.

- فعال: متبقي أكثر من حد التنبيه.
- ينتهي قريباً: من يوم واحد حتى حد التنبيه (7 أيام افتراضياً).
- منتهي: يوم الانتهاء أو بعده. اليوم نفسه يظهر «ينتهي اليوم».
- موقوف: إيقاف إداري يتقدم على حالة المدة.

التجديد الساري يضيف المدة إلى نهاية الاشتراك الحالية، والمنتهي يبدأ من اليوم. التجديد لا يزيل الإيقاف الإداري. إعادة التفعيل لا تجدد اشتراكاً منتهياً ولا تنشئ جلسة اتصال حقيقية. تتم مراجعة الانتهاء عند الفتح وكل 30 ثانية أثناء استخدام الصفحة؛ التشغيل الدائم والإيقاف الحقيقي مستقبلًا مهمة Backend.

تعديل تعريف الباقة لا يغير السرعات المخصصة للمشتركين الحاليين؛ تغيير باقة المشترك يطبق سرعاتها. الأسعار تقديرية، ولا توجد مدفوعات فعلية. تغيير العملة يغير العرض فقط دون تحويل القيم. مبالغ التجديد تحفظ بسعرها وقت العملية.

## الأمان والمرحلة التالية

هذه النسخة ليست نظاماً إنتاجياً. وضع D1 محمي بكلمة مرور مدير واحدة وجلسة HttpOnly موقعة لمدة 12 ساعة، مع تحديد محاولات الدخول وحماية Origin للكتابة وتحقق من جهة الخادم. جميع كلمات المرور داخل العينات تجريبية؛ لا تدخل بيانات PPPoE حقيقية أو أسرار راوتر في هذه المرحلة. الواجهة لا تتضمن حقول بيانات وصول للراوتر ولا تتصل بـ RouterOS مباشرة.

البنية التالية مستهدفة:

```mermaid
flowchart TD
    A[ISP Manager Frontend] --> B[Secure Backend API]
    B --> C[MikroTik RouterOS API]
    C --> D[PPPoE / Profiles / Queues / Sessions]
    D --> E[المشتركون]
```

تمت إضافة Backend لبيانات النسخة التجريبية المشتركة. المرحلة التالية تشمل حسابات متعددة وصلاحيات وجداول علائقية وجدولة انتهاء الاشتراكات والاتصال الفعلي بالراوتر. يحتفظ الخادم وحده بمعلومات RouterOS في متغيرات سرية، مع تشفير بيانات الوصول وHTTPS وتدقيق الأوامر. لا تحفظ أسراراً في GitHub أو Frontend.

## النشر على Cloudflare Pages

اربط هذا المستودع فقط: `storeqn/isp-manager-demo`.

- Framework preset: Vite
- Build command: `npm run build`
- Build output directory: `dist`
- Node version: `22` أو إصدار أحدث متوافق
- Root directory: جذر المستودع

التنقل يعتمد hash، فلا يحتاج إعداد إعادة كتابة للمسارات. وضع الخادم يتطلب المتغير السري `ADMIN_PASSWORD` والربط `DB` كما يلي.

لـ GitHub Pages يمكن ضبط `VITE_BASE_PATH=/isp-manager-demo/` عند البناء. Cloudflare يستخدم `/` الافتراضي.

## PWA والتحديثات

التثبيت يتطلب HTTPS أو localhost. على iPhone: Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية. على Android أو Desktop: خيار تثبيت التطبيق في المتصفح.

Service Worker يعمل في الإنتاج فقط، ويستخدم **network first** دون تثبيت ملفات قديمة مسبقاً. ملفات Vite تحمل أسماء مرتبطة بمحتواها. الصفحة وWorker وManifest لا تعتمد كاشاً طويل الأمد، بينما الملفات ذات الأسماء المميزة تخزن طويل الأمد. الإصدار الجديد يظهر عند إعادة الفتح أو إعادة التحميل مع اتصال متاح. الموارد التي لم تفتح من قبل تحتاج اتصالاً أول مرة، ولا تدّعي النسخة تنزيل كل الصفحات تلقائياً.

## تفعيل البيانات المشتركة على Cloudflare

1. أنشئ قاعدة `isp-manager-db` واربطها بالمشروع باسم `DB`، في بيئة Production.
2. نفّذ محتويات `migrations/0001_app_state.sql` ثم `migrations/0002_login_limits.sql` في D1 Console. كلاهما قابل للتكرار دون حذف بيانات.
3. في إعدادات المشروع، Variables and Secrets، أضف **Secret** باسم `ADMIN_PASSWORD`: كلمة مرور عشوائية قوية من 16 إلى 256 حرفاً. لا تستخدم بادئة `VITE_`؛ لا تدخلها في الملفات أو GitHub أو المحادثة.
4. أعد النشر بعد حفظ الربط والمتغير. يحتفظ `functions/` بموقعه في جذر المستودع؛ Cloudflare يبني Functions بالإضافة إلى `dist/`.
5. صدّر أولاً نسخة JSON من الجهاز الذي يحتوي على بياناتك الصحيحة. عند أول تسجيل دخول، اختر نقل بيانات هذا الجهاز أو ارفع النسخة الصحيحة. البديل هو مساحة فارغة مع الباقات الافتراضية، بتأكيد صريح.
6. افتح الرابط نفسه في المتصفح والتطبيق وسجّل الدخول بالكلمة نفسها. تتم قراءة التغييرات عند الفتح والعودة للواجهة وكل 30 ثانية أثناء ظهور الصفحة.

`/api/session` يعلن حالة إعداد الخادم والجلسة دون بيانات المشتركين. `/api/login` و`/api/logout` لإدارة جلسة الدخول. `/api/state` يتطلب الجلسة للقراءة والكتابة. تحفظ الكتابة البيانات أولاً ثم تؤكد الواجهة النجاح، وتستخدم مقارنة `revision` ذرية؛ التعارض يرفض الكتابة ويحدّث النسخة المعروضة، دون دمج تلقائي أو إعادة عملية تجديد تلقائياً.

حد جسم الطلب المشترك 512 KB؛ النسخة مناسبة لتجربة صغيرة. البيانات في صف JSON واحد متوافق مع تنسيق النسخ الاحتياطي الحالي. تبقى التقارير والسجلات والباقات والمشتركون ضمن نفس اللقطة لضمان الاتساق. قبل تحويله إلى نظام إنتاجي، انتقل إلى جداول منفصلة وعمليات API محددة وصلاحيات متعددة.

العمل المشترك يحتاج الإنترنت. لا يتم حفظ بيانات API في Service Worker أو localStorage، ولا يسمح بإجراء تعديل دون تأكيد الخادم. يبقى الوضع المحلي المستقل متاحاً عند التطوير عبر Vite أو استضافة الملفات الثابتة وحدها. لا تمزج الوضع المحلي مع المشترك وتتوقع المزامنة تلقائياً.

تسجيل الخروج يمسح كوكي الجهاز الحالي. الجلسات الموقعة تنتهي خلال 12 ساعة؛ تغيير Secret كلمة المرور ثم إعادة النشر يبطل جميع الجلسات السابقة. لا توجد حالياً إدارة مستخدمين أو إلغاء جلسات منفردة على الخادم. تحديد المحاولات 10 لكل IP في فترة ثابتة من 15 دقيقة، مع سقف عام 1000؛ بيانات IP محفوظة كبصمة HMAC فقط.

ملفات الربط: `functions/api/[[path]].js`، `server/api.js`، `src/services/cloudService.js`، `src/services/store.js` و`src/components/CloudGate.jsx`. الاختبارات الإضافية تتحقق من SQL حقيقي في SQLite ومن الواجهة في سياقَي متصفح منفصلين عبر مسارات API محلية. يبقى الاختبار الفعلي على نشر Cloudflare وعلى iPhone خطوة مستقلة بعد إعداد الحساب.
